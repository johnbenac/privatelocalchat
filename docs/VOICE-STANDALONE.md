# The standalone Kokoro engine package

`ops/voice/standalone/` builds a folder that any web page can host to speak English with Kokoro-82M, without Private Local Chat: the main-thread engine (`engine.mjs`, shipped as
`kokoro-engine.mjs`), a same-origin worker (`worker.src.mjs`, bundled as `worker-kokoro-standalone.js`), the ONNX Runtime Web 1.31.1 files, a pinned file list, the notices and the
corresponding source. It was built for the lipsync demo (board T1013); its own README (generated by the build) states every size and hash.

* **Build:** `cd ops/voice && npm ci --ignore-scripts && cd ../.. && node ops/voice/standalone/build.mjs <folder> [--voices af_heart,am_michael,af_alloy]`. Deterministic for the pinned versions.
* **Differences from the app's own engine (`chat/voice/voice-engine.mjs`, `worker-kokoro.js`):** it takes the file list and the CDN base as arguments (no `window.APP_CONFIG`); the main thread
  downloads and verifies every file (size, SHA-256) and hands the bytes to the worker, which never reads storage; the worker is always single threaded (no cross-origin isolation needed); it
  yields between chunks so `cancel` is seen; each chunk carries the phoneme string (`ipa`); only the voices in the list are fetched. The Kokoro pipeline (`chat/voice/voice-kokoro.mjs`) is the
  same file, so the audio is sample-for-sample the same.
* **Tests:** `tests/kokoro-standalone.test.mjs` (the engine with fake network and worker: list validation, every refusal, the cache, protocol, parallel use, and each guard broken once) and
  `tests/e2e/kokoro-standalone.e2e.mjs` (real worker and real pinned files on a page with no cross-origin isolation under `script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'`; corrupted,
  truncated, over-long and missing downloads refused; no `crypto.subtle`; cancel). The browser test needs the network and `node scripts/e2e.mjs kokoro-standalone`.
* **Not proven:** real-time speech on a phone, Safari/iOS/Firefox.
* **Home of the code:** it lives here because the plc team owns it and builds it; it is shared code in practice (lipsync vendors it). If Private Local Chat should use it too, or a third team
  needs it, it belongs in its own repository and versioned package (`/cosmoshot/tools/docs/VENDORING.md`): a decision for John, not made here.
* **Known issue found on the way (not fixed here):** the notice file of the app's own worker, `chat/vendor/voice/worker-kokoro.js.LEGAL.txt`, still says Private Local Chat is released under GPL-3.0;
  the licence is AGPL-3.0-only. It is a built file: fixing it means rebuilding the worker with a corrected `ops/voice/build-worker.mjs`.


## The threads variant (`build.mjs --variant threads`)

For a page that IS cross-origin isolated (COOP same-origin, COEP require-corp): `node ops/voice/standalone/build.mjs <folder> --variant threads` writes the package `kokoro-engine-threads` with the worker `worker-kokoro-standalone-threads.js`. It is the same worker and engine with exact text patches (`variant-threads.mjs`; the build stops if a patch no longer applies), so the default package stays byte-identical:

* `engine.load({ threads })` (default 1): the worker uses `min(threads, 4, hardwareConcurrency)` threads only when `crossOriginIsolated` is true, otherwise one; `engine.status().threads` and the load result say how many were used. No `blob:` in `worker-src` is needed (tested under `default-src 'self'; script-src 'self' 'wasm-unsafe-eval'; worker-src 'self'`, `tests/e2e/kokoro-threads.e2e.mjs`).
* `engine.speak(text, { firstChunkSplit: { minChars } })` (default off): the first chunk is cut at the first comma, semicolon or colon at least `minChars` characters in (not inside a number, leaving at least 12 characters), so the first sound arrives sooner. Measured on this host (loaded): first sound 10.4 s for a 6 s sentence as one chunk, 3.8 s with the first chunk cut at the comma.
* Whether threads are faster on a phone is NOT known: on this loaded host four threads were not faster than one.
