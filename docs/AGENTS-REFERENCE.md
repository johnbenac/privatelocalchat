## Vendored packages, offline, voice picker (the full text)

- **`runtime/providers/` is NOT edited here.** It is a read-only copy of the shared package `model-runtime` (owner plc, source of record: the repository `/cosmoshot/model-runtime`, origin `gitlab.benac.dev/cosmoshot/model-runtime`), pinned by exact version and SHA-256 in `vendor.lock.json`; `tests/vendor-lock.test.mjs` fails the build on an edited, added or removed file, using the check that is itself vendored here as `tools/vendor-check/` (package `vendor-check`, owner devops, also pinned in the lock; take a new version the same way, never edit it). To change the runtime: change it in `model-runtime`, bump its version, run its `scripts/package.py publish --apply`, then take the version here with `/usr/bin/python3 /cosmoshot/tools/ops/vendor_check.py pin ...` (`/cosmoshot/tools/docs/VENDORING.md`) in one commit with the new files. The app passes its own settings store (`createModelHost({settings: appLocal})`) and serves the two WebLLM libraries itself.

- **`vendor/authored-profiles/` is NOT edited here either.** It is a read-only copy of the package `authored-profiles` 1.2.0 (owner cosmogenitor, registry `cosmogenitor/authored-profiles`), pinned by exact version and SHA-256 in `vendor.lock.json` and checked by `tests/vendor-lock.test.mjs`. It is the shared validator for Cosmogenitor character packages. The app loads only its **neutral entry** (`neutral/index.mjs`, via `chat/presentation/reader.mjs`; `chat/presentation/open-bundle.mjs` takes the validator as an argument), and the build ships exactly that entry's ten-file import closure in every target, because a copy made for others must carry nothing of ours (`tests/neutrality.test.mjs`); the package's tests, examples and the rest never ship (`tests/presentation-build.test.mjs`). See `docs/CHARACTER-PACKAGE-PREVIEW.md`. Take a new version the same way as `model-runtime` (`/cosmoshot/tools/docs/VENDORING.md`), never edit it.

- **Offline (`docs/OFFLINE-PLAN.md`, `chat/connection/`, `runtime/offline-readiness.mjs`, `chat/shell/connection-pill.mjs`, `chat/shell/offline-section.mjs`)**: `createConnectionGlue` (created in `index.html`, read as `window.plcApp.offline`) holds the online/offline state (the browser's flag, failed requests, and a direct check of the app's own origin), the checklist facts and the fixes; the shell draws the pill and Settings > Models > Ready for offline use. A window that looks private (Safari: no OPFS, no Blob in IndexedDB, no service worker; `chat/connection/private-mode.mjs`) is told so first in the checklist and in a toast, because it can keep nothing for offline use; where OPFS cannot be opened models are kept in the Cache API (`runtime/providers/cache-api-backend.mjs`) and the 105 MB SmolLM2-135M is the default. A failed provider request is called offline only when the connection layer agrees; a provider on this device is never called a problem offline. The service worker (`scripts/service-worker.js`) saves the app, reports how many model runtime files are saved, and saves the rest on request. `tests/offline-precache.test.mjs` fails if a shipped or imported file is left out of its list; `tests/e2e/offline.e2e.mjs` runs on every push, `offline-model.e2e.mjs` and `offline-download.e2e.mjs` (real model) are release checks. The dev-only network switch on `dev.privatelocal.chat` simulates offline on a phone.

- **Voice picker (`chat/voice/voice-choice.mjs`, the voice pill and Settings > Voice in `chat/shell/shell.mjs`, `chat/voice/voice-engine.mjs`, `runtime/voice-pick.mjs`, `ops/voice/`)**: the person chooses how answers are read aloud from a voice menu beside the model menu: the system voice, or a downloaded voice (Kitten, Kokoro: ONNX Runtime Web in a worker with an eSpeak NG phonemizer, bundled into `chat/vendor/voice/worker*.js`). Choosing a voice that is not downloaded downloads it at once. NOTHING is gated by a device test: `runtime/voice-pick.mjs` only produces advice ("recommended" / "may be slow"); a failure is explained and the next try asks for one confirmation and goes ahead. Downloads use the same worker OPFS writer as the language models. The combined app is AGPL-3.0-only (it must be GPL-compatible because of eSpeak NG, which is GPL-3.0-or-later) (`THIRD-PARTY-NOTICES.md`). Plan and evidence: `docs/VOICE-ENGINE-PLAN.md`, `docs/evidence/voice/`.
